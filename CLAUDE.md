# CLAUDE.md

Заметки для работы с этим репозиторием.

## Что это

Три программы на Go (Windows, интерфейс на русском):

* **агент** (`cmd/asiair-agent`, `internal/agent`, окно — `internal/gui`) — на ПК в обсерватории рядом с ASIAIR: читает его SMB-шары (`internal/source`), отправляет кадры на приёмник, удаляет файлы на ASIAIR по командам приёмника, сам обновляется;
* **приёмник** (`cmd/asiair-receiver`, `internal/receiver`, страница — `internal/receiver/web/index.html`) — дома: принимает кадры, веб-страница, раздаёт агенту обновления;
* **сортировщик** (`cmd/asiair-sorter`, `internal/sorter`) — раскладка кадров для Siril, планировщик ночи.

Протокол агент ↔ приёмник — `internal/protocol`. Новые поля добавляются так, чтобы старые агенты и приёмники продолжали работать (поле `omitempty`, отсутствие поля = старое поведение).

## Главное правило: агент должен быть доступен всегда

Агент работает в удалённой обсерватории без присмотра. Если он упал или завис, до утра (или до поездки) никто его не поднимет, а ночь съёмки не будет передана. Поэтому любое изменение агента продумывается с вопросом «что будет, если это сломается или будет медленным»:

* **Не блокировать цикл связи** (`pollLoop`/`poll`). Долгие дела (удаление тысяч файлов, проверка скорости, сбор журналов, обновление) идут в своих горутинах, а `poll` только ставит их в очередь. Иначе приёмник видит агента «не на связи», пустой график скорости и т. п. (так было с удалением 3000 файлов до 1.36).
* **Пачки вместо поштучной работы**: результаты команд — одним запросом (`/api/results`), состояние сохраняется один раз на пачку, а не на файл.
* **Паника не роняет агент**: все циклы запускаются через `a.guard` (перезапуск цикла после паники); новые долгоживущие горутины — тоже через него или с `recover`.
* **Если всё же упал — поднимается сам**: служба Windows перезапускается диспетчером служб; в трее работает сторож (`svc.StartGuardian`), который запускает агента снова после аварийного выхода. Причина сбоя пишется в `asiair-agent.crash` (`svc.CatchCrashes`) и при следующем запуске уходит на приёмник событием.
* **Перед важными действиями — событие на приёмник** (`a.event`, а перед действиями, после которых агент может не вернуться, — `a.eventWait`): обновление, перезапуск, удаление, поиск ASIAIR, смена сети. Так по странице приёмника видно, что агент делал перед тем, как пропал.
* **Сеть меняется** (другой Wi-Fi, другой адрес): соединения старой сети сбрасываются сразу (`networkChanged`), всё переподключается само; передача продолжается с места обрыва.
* Таймауты на всех сетевых операциях; повтор с паузой вместо выхода с ошибкой; никаких `log.Fatal`/`os.Exit` в работающем агенте.
* Обновление агента с откатом (`internal/update`): новая версия, не вышедшая на связь, откатывается сторожем обновления.

## Обновления только при реальных изменениях

Релизная сборка (`.github/workflows/release.yml`) считает для каждой программы отпечаток кода (`protocol.Build` — хеш сборки без номера версии) и кладёт их в `builds.json` релиза. Программа, чей отпечаток в новом релизе тот же, не скачивает и не перезапускает себя (`update.Unchanged`), а страница приёмника пишет «обновлений нет».

## Сборка и проверки

```sh
go build ./...                 # Linux-части
GOOS=windows go vet ./...      # всё, включая окна (walk)
go test ./...
```

Перед коммитом: `gofmt -l .` пусто, `GOOS=windows go vet ./...` чисто, тесты проходят. JavaScript страницы приёмника проверяется так: вытащить `<script>` из `index.html` и `node --check`.

## Стиль

* Комментарии в коде — по-английски, короткие; всё, что видит пользователь (журнал, окна, страница), — по-русски.
* Сообщения коммитов — по-английски, в стиле существующих («Agent: …», «Sorter: …»).
* Документация для пользователя — `README.md` (по-русски); новые возможности описываются там же.

## Выпуск версии

Работа ведётся в ветке, затем слияние в `main` (merge-коммит `Merge branch '…': …`), затем тег `vX.Y.Z` на `main` и `git push origin vX.Y.Z` — workflow `Release` собирает файлы и создаёт релиз. Номер: новая возможность — минорная версия, исправление — патч.
